# График уровня топлива — 3 способа

Задача: построить максимально точный график уровня топлива в баке за день.
`charges`/`discharges` — это только **события** (резкие скачки выше порога), не сам уровень.

## Способ 1 — сырой ряд датчика (ЛУЧШИЙ) ✅
`servlet/Controller` → `getSensorsData` (НПС) / `GET_SENSOR_DATA` (наш).
Поточечные показания датчика: НПС ~135 точек/день (шаг ~5 мин), наш ~6000 (шаг ~5 сек).
**Требует web-сессию** (sess+JSESSIONID). Подробно → [controller-servlet.md](controller-servlet.md).
Один запрос покрывает хоть весь месяц. Это и есть кривая, которую рисует web-интерфейс.

## Способ 2 — реконструкция из getFuelStats (дёшево, моделированно)
Токен-API, без сессии. Из `extData.tankStats[]`: `remainStart`, события `chargeList`/
`dischargeList` (время+объём), `modeRates` (расход WORK/MOVE), `engineTime`/`idleTime`.
Кривую можно собрать как: убывание по расходу в режимах работы + ступени на заправках/сливах.
Точно по событиям, но между ними — модель, а не измерения.

## Способ 3 — скользящее окно getMonitoringStats (fallback, только токен)
Если нет web-сессии. Дробим период на мелкие окна (`HH:mm`), у каждого берём
`valueBegin`/`valueEnd` = измеренный уровень на границах окна.
- **Проверено:** границы соседних окон стыкуются (`valueEnd[i] ≈ valueBegin[i+1]`), т.е.
  это реальные показания датчика, а не модель. Окно ловит и заправки (скачок `valueBegin→End`).
- Стоимость: запросов = (минуты / шаг); лимит 1 запрос/31с на `idMO`. 3ч работы при шаге
  5 мин ≈ 36 окон ≈ ~19 мин на машину.
- Потолок точности = интервал сообщений трекера; окно мельче него даёт повтор того же
  значения. Демо: `demo_fuel_window.py`.
