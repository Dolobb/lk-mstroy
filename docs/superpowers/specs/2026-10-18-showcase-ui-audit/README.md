# UI-аудит ЛК Мстрой под шоукейс — общий регламент (Claude + Codex)

## Зачем
ЛК будут показывать в видео и на скриншотах в портфолио фриланса. Планка — **шоукейс**, а не «на проде и так работает».
Всё, что глаз зрителя цепляет на скриншоте, — дефект: обрезанные числа, элементы за краем экрана, горизонтальный скролл
там, где его можно избежать, кривая центровка, слипшиеся элементы, разнобой отступов, неконсистентные компоненты,
пустые/сломанные состояния, артефакты тёмной темы.

## Калибровка (реальные дефекты, найденные человеком — такой уровень внимательности ожидается)
1. /analytics, «Таблица»: основная таблица уходит под правый сайдбар «Объекты» → горизонтальный скролл, пользователь видит неполные колонки.
2. /analytics, сайдбар «Объекты»: вкладка «Без объекта» уезжает за правый край экрана (P0 — ломает интерфейс).
3. /samosvaly, Заявки → раскрытая карточка, Гант-строка: числа в окошках («17%», «22%», «≈4») не влезают и режутся рамкой окошка.
4. /samosvaly, правый сайдбар: проценты в кольцевых диаграммах («46%», «51%») стоят не по оптическому центру кольца, а ниже. Тонко, но режет глаз. Ищется только зум-кропом.
5. Верхнее меню (все страницы): пункты нагорожены друг на друга, основные сервисы (Главная…Аналитика) стоят вплотную к вспомогательным (Выдача топлива, Отчёты, AI Demo, Серверы, Состояние ТС, Гео), подписи переносятся в 2 строки.

## Среда
- Фронт: `http://localhost:5173` (Vite dev, HMR). КИП — iframe на `:3001`, Гео — iframe на `:3003/admin`, «Выдача топлива» — `/vydacha-topliva/index.html`.
- Скриншоты: `node` + `.ui-audit/tools/lib.mjs` (playwright-core, установленный Chrome, headless). См. JSDoc в файле.
  - `open(path, {theme:'light'|'dark', w, h, dpr})` → `{page, close}`; `snap(page, 'codex/x1/03-name-light-1470')`;
  - `overflowReport(page, selector)` — элементы, чей контент режется рамкой; `offscreenReport(page)` — что вылезает за правый край + горизонтальные скроллы.
  - Для мелкой геометрии (центровка, обрезка цифр) — `dpr: 2` и `snap(..., {clip:{x,y,width,height}})`, затем СМОТРЕТЬ кроп.
- **Вьюпорты:** основной — **1470×830** (MacBook пользователя, на нём будет запись видео). Плюс 1920×1080 и 1280×800 для начальных состояний.
- **Темы:** обе. Основная для записи — **светлая**, тёмная обязательна для проверки контраста/артефактов.

## Правила обхода
- Ходить как пользователь: каждая страница → все вкладки/режимы → кликать, раскрывать, скроллить, открывать дропдауны, тултипы (hover), модалки, переключать даты/периоды, пустые состояния, поиск.
- **После каждого шага — скриншот и анализ** (смотреть картинку глазами, а не только детекторы). Детекторы — подсказка, не замена.
- Разрешено: идемпотентные действия (обновить, пересчитать отображение, открыть диалог, отменить). **Запрещено:** удаления, рестарт сервисов, сабмит форм, создающих/меняющих данные, выдача топлива, перевыгрузки пайплайнов.
- **Не редактировать код** на этапе аудита. **Не трогать git.**

## Формат находок — `.ui-audit/findings/<area>.md`
Шапка: зона, кто аудировал, вьюпорты/темы, список пройденных сценариев (чеклист покрытия).
Каждая находка:

```
### <ID> [P0|P1|P2|P3] <короткое название>
- Где: <страница> → <состояние/шаги воспроизведения>; тема; вьюпорт
- Скрин: .ui-audit/shots/...png (+ кроп, если есть)
- Что не так: конкретно и измеримо (px, какие элементы, что обрезано)
- Источник: <file>:<line> (компонент/стиль, который это рисует) — найти в коде
- Фикс: конкретно (что поменять в JSX/CSS), без «рассмотреть»
- Объём: S (< 15 мин) | M (< 1 ч) | L (> 1 ч)
```
Severity: P0 — ломает интерфейс/видно сразу (за краем, перекрытие, нечитаемо); P1 — заметно на скрине/видео, выглядит сыро;
P2 — мелкая неряшливость (отступы, выравнивание, разнобой); P3 — полировка.

ID: Claude — `C<зона>-NN`, Codex — `X<зона>-NN`.
Скрины: `.ui-audit/shots/claude/<зона>/...`, `.ui-audit/shots/codex/<зона>/...`.
