## Что это

Бэкенд **приложения выдачи топлива** (АТЗ): принимает офлайн-данные с Android-планшетов
водителей (смены, выдачи/получения топлива, фото ТТН) и отдаёт их админ-сервису ЛК Мстрой.
Первый writeable-из-интернета компонент ЛК → **безопасность строже обычного**.

Полный контекст (источник истины) — Obsidian vault
`02-Projects/Приложение выдачи топлива/`:
- `Архитектура.md` — §2 модель данных, §4 эндпоинты, §3 синк
- `Tech-Interview-Decisions.md` — принятые продуктовые/технические решения
- `Architecture/Data-Model.md` — маппинг полей TIS, seed
- `Process/Shift-Model.md` — бизнес-правила смены и остатка
- `Agent-Orchestration.md` — кто что делает

## Модель данных — 8 таблиц

Полная DDL — `Архитектура.md §2`. Таблицы:
`drivers · atz · organizations · vehicles · shifts · fuel_dispense_events · fuel_receipt_events · event_edits`

**Жёсткие инварианты (НЕ нарушать):**
- **PK всех событий** (`shifts`, `fuel_dispense_events`, `fuel_receipt_events`) — **client-generated UUID**.
  Сервер их НЕ генерирует, принимает как есть → идемпотентность.
- Sync = `INSERT ... ON CONFLICT (id) DO UPDATE` (upsert). Повторная отправка не дублирует.
- `happened_at_client` — авторитетное время события («когда заправил»).
  `received_at_server` — отдельная серверная метка. **Никогда не подменять одно другим.**
- Мягкое удаление: `is_deleted=true`, физически не удалять (нужно для аудита).
- Каждая правка пишет строку в `event_edits` (before/after jsonb).
- `organizations.tis_org_id` (int, UNIQUE, NULL) — ключ дедупликации при seed из getPassports;
  NULL для организаций с `source='driver'` (решение 2026-06-12).
- «Один АТЗ = одна открытая смена» закреплено и на уровне БД: частичный уникальный индекс
  `uniq_open_shift_per_atz ON shifts(atz_id) WHERE status='open'` (страховка от гонок; 2026-06-12).
- `vehicles.tis_id` — UNIQUE (нужен для `ON CONFLICT` при seed; NULL у source='driver' допускается многократно).
- Справочники (`organizations`, `vehicles`, `atz`) имеют `updated_at` — основа дельты `/bootstrap?since=`.
  Любой upsert/update справочника ОБЯЗАН обновлять `updated_at` (иначе планшеты не увидят правку).

## Эндпоинты (контракт)

| Метод | Путь | Auth | Назначение |
|-------|------|------|-----------|
| POST | `/auth/login` | — | `{login, pin}` → JWT + профиль водителя (+ данные для офлайн-кэша) |
| GET | `/bootstrap?since=` | JWT | справочники (vehicles, organizations, atz водителя) + последние смены, дельта по `since` |
| POST | `/sync` | JWT | батч событий с client-UUID → идемпотентный upsert. Ответ: присвоенные id, пересчитанный остаток АТЗ, конфликты |
| POST | `/uploads/ttn` | JWT | multipart фото ТТН по UUID receipt-события → стрим на диск → `ttn_photo_status='uploaded'` |
| GET | `/vehicles?q=` | JWT | автокомплит (опц., НЕ реализован — клиент ищет в bootstrap-кэше) |
| GET | `/admin/shifts`, `/admin/shifts/:id`, `/admin/drivers/:id`, `/admin/atz/:id` | **Bearer** | для админ-сервиса ЛК (`/admin/shifts/:id` — drill-in с событиями и правками, добавлен 2026-06-12) |
| GET | `/health` | — | `{ok:true}` |

- Водитель (планшет) → **JWT** (логин+PIN).

## Бизнес-правила (из интервью)

- **Один АТЗ — одна открытая смена.** При `shift/open` сервер отклоняет, если на этом `atz_id`
  уже есть смена `status='open'` → понятная ошибка водителю.
- **Остаток АТЗ** = калибровка + Σ(receipts) − Σ(dispense) по АТЗ (только `is_deleted=false`).
  **Пересчитывается сервером при каждом `/sync`.** Сервер — источник истины.
- Стартовый остаток АТЗ выставляется **вручную через psql** при запуске пилота (не через API на MVP).
- Новые ТС/организации от водителей: `source='driver'`, организация без выбора → `kind='hired'`.
- Seed ТС — одноразовый из `seed/` (НЕ делать cron getPassports на MVP).

## ⚠️ Зоны, которые Codex НЕ трогает без ручного ревью Claude

**`POST /sync` (services/sync) — критичный модуль.** Идемпотентность, пересчёт остатка,
enforce «один АТЗ = одна смена», разрешение конфликтов. **Пишет/ревьюит Claude.** См. `Agent-Orchestration.md`.
Codex может готовить вокруг (роуты, валидация, типы), но саму логику upsert — только под ревью.

## Безопасность (первый внешний writeable-сервис)

- Валидация zod на КАЖДОМ входе. Невалидный вход → 400, не падать.
- Rate-limit на `/auth/login` (брутфорс PIN) и `/uploads/ttn`.
- Фото: проверять MIME/размер, стримить на диск, **жать клиентом до ≤500 КБ** (бэк дополнительно ограничивает размер).
- Никаких секретов в коде/гите — только `.env` (в `.gitignore`).
- SQL только через Drizzle (параметризация), без конкатенации строк.
