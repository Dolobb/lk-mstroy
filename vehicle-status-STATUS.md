2. **Закрепить (Pin)** — колонка слева с иконкой Pin (lucide-react). Закреплённые ТС всегда наверху, фон `bg-primary/5`, иконка повёрнута на 45°. Не пагинируются.

## Текущая проблема: Сводная по МиМ — сдвиг столбцов

### Симптомы (из данных в БД до фикса unmerge)
```
id:2510  plateNumber:"0024ОА72"  branch:"ХМАО"  techStatus:"МО87"
id:2514  plateNumber:"0025ОА72"  branch:"Тюменская область"  techStatus:"МО87"
```
- `techStatus` = "МО87" — это код филиала, а не тех. состояние
- `branch` = "ХМАО"/"Тюменская область" — это регион, а не филиал
- Данные сдвинуты на 1 столбец вправо относительно заголовков

### Диагностика показывает
Заголовки строки 1 (сводная по МиМ):
```
Col 0: "№ п/п"
Col 1: "№ в гр."
Col 2: "Марка"            → brand:2 ✓
Col 3: "Гос. №"           → plate:3 ✓
Col 4: "Выработка"
Col 5: "Регион / город"
Col 6: "Объект"
Col 7: "Филиал"
Col 8: "Тех. состояние"
Col 9: "Заявитель"
Col 10: "Вид работ"
```

Но `findHeaderRow()` вернул: `constructionObject:7, branch:8, techStatus:9, workType:11`
- `constructionObject:7` → считывает "Филиал" вместо "Объект"
- `branch:8` → считывает "Тех. состояние" вместо "Филиал"
- `techStatus:9` → считывает "Заявитель" вместо "Тех. состояние"
- `workType:11` → выходит за границы (всего 11 столбцов, индексы 0-10)

### Причина
В строке 1 листа "Сводная по МиМ" есть **merged cells**. `XLSX.utils.sheet_to_json({ header: 1 })` не расклеивает merged-области — пустые ячейки слияния получают `""`. Из-за этого:
- В строке заголовка "Объект" может находиться в idx 7 вместо 6 (между ними пустая ячейка слияния)
- В строках данных значение "Филиал" также сдвигается

### Что сделано для исправления
Добавлена функция `unmergeSheet()` которая:
1. Читает лист по ячейкам через `XLSX.utils.encode_cell`
2. Расклеивает merged-области: копирует значение из `m.s.r/m.s.c` во все ячейки диапазона слияния
3. Заменила `sheet_to_json` в обоих местах (runSync, runDiagnostic)

### Статус фикса
Код написан и компилируется (`tsc --noEmit` чисто), но **не протестирован** — сервер был перезапущен, но после `unmergeSheet`:
- Нужно сделать `POST /api/vs/vehicles/sync` для пересинхронизации
- Нужно проверить данные по "Сводная по МиМ" — что `branch`, `techStatus`, `constructionObject` теперь корректны
- Нужно прогнать `GET /api/vs/vehicles/diagnostic` для сравнения маппинга до/после

## Другие известные проблемы

### isBroken() — неопознанные статусы
Следующие статусы из "Сводная по МиМ" возвращают `isBroken=false`, хотя смысл неизвестен:
- `"МО15"`, `"МО29"`, `"МО36"`, `"МО87"` — выглядят как коды подразделений/филиалов, случайно попавшие в колонку тех. состояния
- `"СКТ"` — неизвестный статус
- `"СтройКранТюмень"` — название организации

### Диспозиция ОГТР и МС11 — case-варианты статусов
Уникальные статусы включают дубли в другом регистре:
- `"Исправен"` и `"исправен"`
- `"Неисправен"` и `"неисправен"`
- `"Требует ремонта"` и `"требуется ремонт"` и `"требует ремонта"` (орфография)
- `"Частично исправен"` и `"частично исправен"`

`isBroken()` работает корректно (`.toLowerCase().includes()`), но в БД и фронтенде они отображаются как разные значения. Дедупликация по регистру на фронтенде уже реализована в `uniqueSorted()`.

### Нет столбца vehicleType
"Сводная по МиМ", "МС 11 Краны (новаяновая)", "Самосвалы МС11", "Диспозиция ОГТР и МС11" — не имеют или имеют другой столбец "Тип ТС". Для "Стягачи" и "ВЕЗДЕХОДЫ" поле `vehicleType` определяется из "Наименование техники" вместо "Тип ТС".
